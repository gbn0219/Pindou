# 图纸导出与坐标系统优化说明

> 状态：已按方案实施（2026-08-06），代码改动完成并通过全部单测；剩余真机验证项见第 6 节。
> 依据：CodeGraph 索引（38 文件 / 487 节点 / 724 边）+ 源码逐文件核对 + 官方文档/社区资料核对。

## 1. 目标

| # | 目标 | 说明 |
|---|---|---|
| 1 | 提高导出图分辨率 | >104 盘（尤其 105~208）保存图片中色块编号模糊，需提高清晰度 |
| 2 | 图库预览第二张 = 生成的图纸 | 应为用户保存到相册的那张图（含色块颜色编号与数目清单），而非纯色效果图 |
| 3 | 背景格显示格子 | 背景（近白区域）没有色块，但也要显示格子；格子里不显示颜色编号 |
| 4 | 导出图四周排号 | 四周加一圈排号，如 52×52 显示 1~52，像坐标系，方便拼豆定位 |
| 5 | 修改页排号/列号 | pattern-edit 修改界面在旁边显示排号与列号，并随放大/缩小/拖动变化 |

## 2. 现状（代码事实）

### 2.1 导出管线

- `miniprogram/utils/pattern.js`：
  - `EXPORT_CELL = 16`、`EXPORT_MAX_DIM = 2048`（画布安全上限）、`GAP = 1`
  - `layoutExport(grid, opts)`：返回 `{ width: gridTotal, height: gridTotal + legendHeight }`
  - `renderExport(ctx, grid, palette, opts)`：画网格 + 底部色号清单，返回布局尺寸
  - `renderGrid / drawCell`：逐格填充 + 可选编号；`noCodeMask`（白色背景连通域）用于隐藏背景格编号
  - `findBackgroundMask`：从四边 flood fill 白色系（RGB 均 ≥230）得到背景掩码
- `miniprogram/utils/export.js`：
  - `renderPatternExport`：整图导出 PNG，画布 ≤2048，输出 `destWidth/destHeight = 画布 × EXPORT_UPSCALE(2)`（输出最大约 4096）
  - `renderPatternJpeg(grid, palette, px)`：与导出图同一布局（含色号与图例），按 px 宽缩放，作缩略图/预览图
  - `renderSquareJpeg`：原图 contain 缩放为方形 JPEG
- `miniprogram/page/pattern/index.js` `saveToGallery()`：
  - `patternFileID` = `renderPatternExport`（PNG，即用户保存到相册的图）
  - `patternThumbFileID` / `patternPreviewFileID` = `renderPatternJpeg(360 / 1080)`
- `miniprogram/page/gallery/index.js`：
  - 预览：`patternPreviewFileID || patternThumbFileID || patternFileID`
  - `backfillThumbs`：老数据缺缩略图/预览图时，从 `patternFileID` 下载 → `renderSquareJpeg` 压缩 → 上传回填

### 2.2 修改页视图模型

- `miniprogram/page/pattern-edit/index.js`：
  - canvas = 可视区域，内容用 ctx 变换呈现（`view = { scale, ox, oy }`），无 CSS 缩放
  - `draw()`：`total = size×(cell+GAP)−GAP`，`scale = min(areaW, areaH)/total`，居中
  - `cellAt(x, y)`：`(x−ox)/scale / (cell+GAP)` 取整定位格子
  - `paintCell` 增量重绘单个格子（`drawCell`）

## 3. 问题根因

### 3.1 编号模糊（目标 1）

- 画布上限 2048，超出时整图等比缩小（`ctx.scale(scale)`），再 `destWidth ×2` 放大。
- 208 盘：网格+图例约 4831px → `scale ≈ 0.42`，格内字号原生仅约 3px，放大 2 倍后约 6px，模糊。
- 105 盘：`scale ≈ 0.68`，字号原生约 4.8px，放大后约 9.5px，仍偏糊。
- 本质：先缩小绘制再放大输出，而非以最终分辨率原生绘制。

### 3.2 图库预览（目标 2）

- 当前代码已用 `renderPatternJpeg`（同一布局、含色号与图例）生成 `patternPreviewFileID`，新保存条目正确。
- 老条目（早期保存的纯色网格预览）由 `backfillThumbs` 从 `patternFileID` 回填，回填产物同样含色号与图例。
- 结论：逻辑上已满足；若用户仍看到旧图，属未回填/未重新保存的历史数据，无需改代码，可触发回填或重新保存。

### 3.3 背景看不到格子（目标 3）

- 背景格填充近白色（如 H1 纯白），格间 GAP 也是白色 → 白色区域内格线不可见。
- `drawCell` 对 `noCodeMask` 只做"不画编号"，没有画格子边框。

### 3.4 无坐标（目标 4、5）

- 导出图与修改页均未绘制排号/列号。

## 4. 方案设计

### 4.1 导出分辨率提升（目标 1）

**文件：`miniprogram/utils/export.js`**

- 新增 `EXPORT_MAX_DIM_HIGH = 4096`。
- 将 `renderPatternExport` 拆为内部函数 `renderPatternExportAt(grid, palette, opts, maxDim)`（async），公开函数先按 4096 尝试，失败（canvas 创建/导出异常）自动回退 `pattern.EXPORT_MAX_DIM`（2048）。
- `EXPORT_UPSCALE = 2` 保持不变（输出最大约 8192）。
- 依据：
  - 官方 `OffscreenCanvas` 自基础库 2.7.0 支持；
  - 社区实测 iOS 真机 canvas 高度 >4096 会静默失败（"canvas is empty"），4096 为保守上限；
  - 官方 `wx.canvasToTempFilePath` 文档未声明 destWidth/destHeight 上限，失败即走回退。
- 预期效果（含 4.4 坐标边距后）：
  - 104 盘：布局约 2359px，不再缩放，输出约 4718px；
  - 208 盘：布局约 4887px → 画布 4096（scale≈0.84），输出约 8192px，格号约 12px（原生绘制，非放大模糊）。
- 风险：208 盘 8192 输出 PNG 体积较大；个别设备 4096 画布失败时自动回退 2048（现状水平）。

### 4.2 图库预览（目标 2）

- **不改代码**。保留 `renderPatternJpeg` 生成 `patternPreviewFileID`，`backfillThumbs` 负责老数据回填。
- 如需彻底清洗老数据，可在图库页增加"重新生成预览"入口（本期不做，仅记录）。

### 4.3 背景格显示格子、不显示编号（目标 3）

**文件：`miniprogram/utils/pattern.js`（`drawCell`）**

- 新增常量 `BG_GRID_COLOR = '#e2e4e8'`。
- `drawCell` 中当 `opts.noCode === true`（背景格）：填充色块后追加浅灰描边：
  `ctx.strokeStyle = BG_GRID_COLOR; ctx.lineWidth = 1; ctx.strokeRect(x+0.5, y+0.5, cellSize−1, cellSize−1)`。
- 影响范围：展示页 / 修改页 / 导出图共用 `renderGrid → drawCell`，背景区域统一显示格子、无编号。
- 注意：格间 GAP 仍为 1px 白色，描边位于格子边缘内侧，不与相邻格重叠。

### 4.4 导出图四周坐标（目标 4）

**文件：`miniprogram/utils/pattern.js`**

- 新增常量：`EXPORT_COORD = 28`（每侧边距 px）、`COORD_COLOR = '#8a919c'`。
- 新增纯函数 `renderCoordinates(ctx, size, cellSize, gap, coord, opts)`：
  - 上/下边：列号 1..size（居中）；左/右边：行号 1..size（居中）；
  - 字号 `font = clamp(10, 18, round(cellSize × 0.7))`；
  - 坐标绘制在当前变换坐标系内（world 坐标），与网格同一坐标系。
- `layoutExport`：
  - `width = gridTotal + EXPORT_COORD × 2`
  - `height = gridTotal + EXPORT_COORD × 2 + legendHeight(items, width)`（图例宽度用整宽）
- `renderExport`：
  - 先铺白底覆盖整幅（边距区域不能透明）；
  - `translate(EXPORT_COORD, EXPORT_COORD)` 后画网格，恢复后调 `renderCoordinates`；
  - 图例画在 `y = gridTotal + EXPORT_COORD × 2`，宽度用整宽。
- 效果：52 盘四周显示 1..52；三位/四位数的盘面（≥100）数字会受格子宽度约束，可能略挤（可接受）。

### 4.5 修改页排号/列号（目标 5）

**文件：`miniprogram/page/pattern-edit/index.js`**

- 新增页面常量 `COORD_SIZE = 28`（与导出一致，world 单位）。
- `draw()`：
  - `world = total + COORD_SIZE × 2`；
  - `scale = min(areaW, areaH) / world`；`ox/oy` 按 world 居中。
- `drawGrid()`：
  - `applyView()` 后 `ctx.save(); ctx.translate(COORD_SIZE, COORD_SIZE)` 画网格，`restore()`；
  - 复用 `pattern.renderCoordinates(ctx, size, cellPx, GAP, COORD_SIZE)` 画排号/列号。
  - 因为坐标画在同一视图变换内，**会随双指缩放/拖动一起变化**。
- `cellAt(x, y)`：`(x−ox)/scale − COORD_SIZE` 后再除 `(cell+GAP)` 定位。
- `paintCell` 增量重绘：两个 `drawCell` 调用前同样 `translate(COORD_SIZE, COORD_SIZE)`（避免偏移错位）。
- 展示页（pattern/index）本期不加坐标（用户未要求；如需可同样处理）。
