# 拼豆图纸生成小程序 — 设计文档

> 日期：2026-08-03（Asia/Shanghai）
> 状态：已获用户确认（含两点补充：每格显示色号、图纸下方列出各色号豆子数量）
> 分支：`codex/pindou-pattern`

## 1. 目标与成功标准

用户导入一张图片 → 选择色系（48/72/144/221 色）与拼豆盘大小（52×52 / 78×78 / 104×104）→ 生成拼豆图纸 → 展示（每格显示色号、图纸下方列出每种色号对应的豆子数量）→ 导出 PNG 到相册 → 进入修改（逐格改色）。

本期**只做原图模式**，不做 AI 卡通化（用户已确认选择 C：卡通化入口先不做）。

成功标准：
1. 三个页面可编译、可交互：主界面、图纸展示页、图纸修改页。
2. 像素化结果保色准确、过渡流畅（平滑区域采样 + CIELAB 最近色匹配）。
3. 展示页每个格子内显示色号；图纸下方按色号列出豆子数量。
4. 导出图片保存到相册成功（含色号与格线，与屏幕展示一致）。
5. 修改页可选中色号并逐格改色，返回展示页后图纸自动刷新。

## 2. 范围外（不做）

- AI 卡通化（用户选择暂不做，主界面不出现该入口）
- 登录、云存储、云端图片处理、分享、撤销/重做、多图、历史记录
- 修改页的批量填充/橡皮擦等进阶编辑
- 色卡的自定义编辑

## 3. 架构

### 3.1 页面

| 页面 | 路径 | 职责 |
| --- | --- | --- |
| 主界面 | `miniprogram/page/index/index` | 选图、选色系、选盘大小、生成图纸 |
| 展示页 | `miniprogram/page/pattern/index` | canvas 渲染图纸（每格色号）、色号数量清单、导出、进入修改 |
| 修改页 | `miniprogram/page/pattern-edit/index` | canvas 逐格改色、底部"小盒子陈列"取色面板 |

在 `miniprogram/app.json` 的 `pages` 数组最前面追加三个页面（首项即启动页）；demo 页面、分包、tabBar、darkmode 等现有配置一律不动。

### 3.2 模块

| 文件 | 职责 |
| --- | --- |
| `miniprogram/data/colors.json` | 色卡静态数据：221 色主表 + 48/72/144/221 套装色号清单 |
| `miniprogram/utils/color.js` | sRGB→CIELAB 换算、最近色匹配、按套装构建调色板（纯函数，可 node 测试） |
| `miniprogram/utils/pattern.js` | RGB 网格→色号网格、色号计数、canvas 绘制/导出（页面调用） |
| `scripts/build-colors.js` | 解析 `docs/拼豆标准色彩RGB与拼豆盘尺寸.md` 生成 colors.json（保留以便后续校正色卡） |
| `tests/color.test.js`、`tests/pattern.test.js` | node 无框架单测 |

### 3.3 数据流

```
主界面：选图 + 设置 → 生成（offscreen canvas 缩放 → getImageData → 最近色匹配）
  → getApp().globalData.pattern = { grid, size, set, imagePath }
  → wx.navigateTo 展示页
展示页：读取 pattern → canvas 渲染 + countColors 统计 → 导出 / 进入修改
修改页：读取 pattern → 涂格后写回 grid → 返回展示页 onShow 重渲染
```

图纸数据只存内存全局缓存（`globalData.pattern`），不做持久化。

## 4. 色卡数据

### 4.1 colors.json 结构

```json
{
  "sets": {
    "48": ["A4", "A6", "..."],
    "72": ["..."],
    "144": ["..."],
    "221": ["A1", "A2", "..."]
  },
  "colors": {
    "A1": { "code": "A1", "hex": "#FAF5CD", "rgb": [250, 245, 205] },
    "...": {}
  }
}
```

### 4.2 数据口径

- 共 221 个色号，RGB 以 docs 第 3 节主表为准（即使套装清单里同色号 HEX 与主表不一致，也以主表为准）。
- 套装清单只用于判定"该色号属于哪个套装"，不覆盖 RGB。
- `scripts/build-colors.js` 生成时断言：221 色完整；48/72/144/221 套装数量正确（48/72/144/221）；每个套装色号都存在于 221 主表；48 ⊂ 72 ⊂ 144 ⊂ 221。

## 5. 像素化算法

采用已确认的**方案一**：

1. 用 `wx.createOffscreenCanvas` 建 N×N（N=52/78/104）画布。
2. 原图按**完整显示（contain）**方式绘制：保持宽高比放入 N×N，白底补齐（透明像素视为白色）。此默认值在用户审阅时确认。
3. `drawImage` 双线性缩放天然完成"区域平均"，颜色过渡流畅。
4. `getImageData` 读取 RGBA；alpha < 128 的像素按白色处理。
5. 每格 RGB 用 CIELAB 距离做最近色匹配，只允许输出当前所选套装内的色号；LAB 在每个套装首次使用时预计算并缓存。

不做抖动、不做额外平滑后处理（避免噪点与过度设计）。

## 6. 页面设计

### 6.1 主界面

- 图片导入区：虚线圆角卡片，点击调 `wx.chooseMedia`（相册/相机，单张）；选中后显示预览与"重新选择"。
- 色系选择：48 / 72 / 144 / 221 四枚胶囊按钮（单选，默认 221）。
- 拼豆盘大小：52×52 / 78×78 / 104×104 三枚胶囊按钮（单选，默认 52）。
- 生成按钮：未选图时置灰；点击后 `wx.showLoading`（生成中…），完成后跳展示页。
- 无卡通化入口。

### 6.2 展示页

- 顶部信息条：色系、盘大小。
- 图纸区：`movable-area` + `movable-view`（支持缩放）内含 canvas 2d；每格绘制色块 + 格线留缝 + 居中色号文字（cellSize=20px、字体 9px、104 格时画布 2080×2080）。
- 图纸下方"颜色清单"：按色号顺序列出本次用到的每种颜色，每项 = 色块小方 + 色号 + × 数量；末尾显示总格数。
- 按钮：导出（高清 PNG 存相册，授权失败引导 `wx.openSetting`）、进入修改。
- 修改后返回本页时 `onShow` 重新渲染，反映修改结果。

### 6.3 修改页

- 图纸区：与展示页相同的 `movable-area/movable-view` + canvas（同样显示色号，便于定位）。
- 触摸格子：`bindtouchstart` 按坐标换算行列（考虑当前缩放比例），命中后高亮该格，并在信息条显示"第 r 行 第 c 列 · 当前色号 X"。
- 取色面板（底部固定，可上下滚动区域，最大高度约 45vh）：按 A/B/C/D/E/F/G/H/M 色系分区，仅显示当前所选套装的颜色；每个色号一个"小盒子"——圆角、内阴影、盒内豆色、盒下色号标签；点选后盒子带选中描边；再点格子即涂色（写回 grid 并重绘该格）。
- 顶部按钮：完成（返回展示页）。

## 7. 导出

- 临时把展示 canvas 设为 N×cellSize（cellSize=20px）分辨率 → 重新绘制（含色号与格线）→ `wx.canvasToTempFilePath` → `wx.saveImageToPhotosAlbum`。
- 授权失败时提示并引导到设置页开启相册权限。
- 导出内容与屏幕展示一致（含色号文字）；如后续需要"无字版"再单独加选项（本期不做）。

## 8. 错误处理（最小集）

- 未选图点生成：按钮置灰，不做弹窗。
- 图片加载失败 / canvas 读取失败：`wx.showToast` 提示后复位 loading。
- 保存相册失败：按错误类型提示（未授权 → 引导设置；其余 → 通用提示）。
- 修改页进入时 `globalData.pattern` 缺失：toast 并返回。

## 9. 测试与验证

### 9.1 node 单测（可自动执行）

- `tests/color.test.js`：
  - colors.json 共 221 色；48/72/144/221 套装数量正确；48 ⊂ 72 ⊂ 144 ⊂ 221；套装色号全部存在于主表。
  - 精确 RGB 命中对应色号（如 A4 的 RGB → A4）。
  - 红色 (255,0,0) 在 221 套装中命中 F 系色号。
  - 48 套装约束：匹配结果永远在 48 清单内。
- `tests/pattern.test.js`：
  - `mapRgbGrid`：给定 2×2 RGB 网格 → 期望色号网格；透明像素 → 白色。
  - `countColors`：已知网格 → 各色号数量正确且按套装顺序排序。

## 10. 假设与待确认点

1. 原图在方形网格上的放置方式默认 **contain（完整显示、白边补齐）**；如需"裁剪铺满"请指出。
2. 导出图片**含色号与格线**，与屏幕展示一致。
3. 修改页与展示页的图纸区支持双指缩放与拖动（104 格时逐格查看/点选必需）。
4. 图纸数据不持久化，退出小程序后重新生成。
