# 像素化平滑优化设计文档（去噪 / 平滑 / 整体效果）

> 日期：2026-08-03（Asia/Shanghai）
> 状态：已实施（方案 A 已审批；v2、v3 修订见文末修订记录）
> 分支：`codex/pindou-pattern`
> 关联：`docs/superpowers/specs/2026-08-03-pindou-pattern-generator-design.md`（本优化的前身设计）

## 1. 背景与问题

当前像素化流程：主页面用 offscreen canvas 按 contain 方式把图片直接缩放到 N×N（双线性）→ 取像素 → 每格 CIELAB 最近色匹配 → 色号网格。

用户反馈的问题：

1. **噪点被放大**：照片的传感器噪点、JPEG 压缩伪影经过最近色匹配后，变成一颗颗孤立错色豆（"盐/胡椒"噪点），观感"花"。
2. **双线性采样不够精细**：从大图一步缩到 N×N，对高对比/细纹理区域容易产生锯齿和偶发杂色。
3. **缺少"整体效果"控制**：目前没有任何机制让相邻豆色过渡更连贯。

## 2. 目标与成功标准

- **保色**：整体色彩保持准确（仍走 CIELAB 最近色，只输出当前套装色号）。
- **平滑**：明显减少孤立杂色豆，相邻区域豆色过渡更自然。
- **保细节**：去噪不能把真正的结构（眼睛、轮廓、细线）抹掉。
- **性能**：104×104 网格处理耗时在数百毫秒级，不显著影响生成体验。
- **可测**：新增算法均为纯函数，node 单测覆盖。

## 3. 这一步需要 AI 吗？——结论：不需要

| 需求 | 适合的手段 |
| --- | --- |
| 去噪 / 平滑 / 整体连贯 | 经典图像处理即可（保边滤波 + 区域平均 + 局部一致性），免费、离线、快、可预测 |
| 卡通 / 插画等风格化 | 才需要 AI（生成式模型），需要 API Key、成本、网络，且是另一种产品形态 |

建议：本期用**经典图像处理**解决"平滑"，与之前"不做 AI 卡通化"的决定保持一致。如果以后想要卡通风，可以单独加一个"AI 优化"云函数步骤（本设计预留接口位置，不实现）。

## 4. 方案对比

### 方案 A（推荐）：经典图像处理三阶段
1. **保边去噪**：中间分辨率（4×N）做 3×3 中值滤波
2. **真实区域平均**：4×4 块平均得到每格平均色（替代单次双线性）
3. **网格孤立点平滑**：匹配色号后，只修正"孤立杂色点"

优点：免费/离线/快；无额外依赖；效果可控可测。
缺点：不会产生插画风（非本需求）。

### 方案 B：方案 A + 误差扩散抖动（可选，默认关）
在大面积渐变（天空、皮肤）上过渡更自然，但近距离会有颗粒感，且代码量增加。
建议：本期不做，保留为后续可选开关。

### 方案 C：接入 AI 增强/卡通化
云函数调用第三方模型，需要 API Key/成本/网络；与当前"原图模式"定位不符。
建议：本期不做；如需，后续作为独立功能（可在主页面预留入口，但本期不加 UI）。

## 5. 方案 A 详细设计

### 阶段 1：保边去噪（中间分辨率中值滤波）

- 主页面先建一个 **4N×4N** 的 offscreen canvas，把原图按 contain 画入（此时的双线性只做一次粗降采样，4N 对 104 格 = 416px，信息保留充分）。
- `getImageData(4N×4N)` 后，在 JS 中对每个像素做 **3×3 中值滤波**：
  - 中值滤波擅长去除椒盐噪点（孤立亮点/暗点），同时比均值/高斯更保边缘；
  - 416×416 ≈ 17 万像素 × 9 次比较，耗时可忽略。
- 实现为纯函数 `medianFilter(imageData, w, h)`（返回同尺寸新 ImageData 数据），可 node 测试。

### 阶段 2：真实区域平均（4×4 块平均）

- 把滤波后的 4N×4N 像素按 4×4 块求平均 RGB，得到 N×N 的"每格平均色"。
- 相比当前"一步双线性"，块平均对每格的采样更忠实、过渡更平滑，且彻底消除锯齿伪影。
- 实现为纯函数 `averageBlocks(data4, size4, block)` → 返回 N×N RGB 数组，可 node 测试。

### 阶段 3：色号映射 + 网格孤立点平滑

- 每格平均色继续走现有 CIELAB 最近色匹配（`color.nearestColor`）。
- 新增纯函数 `denoiseGrid(grid, palette)`：
  - 遍历每个格子，若**该格与上下左右四邻颜色都不同**，且**四邻中 ≥3 个是同一颜色**，则把该格改为那个颜色；
  - 最多迭代 2 次；
  - 只处理"严格孤立点"，因此不会抹掉边缘、轮廓、1 格宽的线（这类结构上下左右至少有两个相邻同色，不满足条件）。
- 该函数可 node 测试：构造含孤立噪点的网格，验证噪点被修正、而细线结构保持不变。

### 主页面管线改动（`page/index/index.js` 的 buildGrid）

```
原图 → 4N×4N offscreen（contain）→ getImageData
     → medianFilter(3×3)          // 阶段1 去噪
     → averageBlocks(4×4)         // 阶段2 每格平均色
     → CIELAB 最近色映射          // 阶段3a（复用 color.nearestColor）
     → denoiseGrid(孤立点平滑)     // 阶段3b
     → grid 写入 globalData.pattern
```

1. `node tests/pattern.test.js`、`node tests/color.test.js` 全部通过；

## 7. 风险与说明

- 中值滤波会让极细纹理轻微"柔化"，但对拼豆这类大颗粒输出影响很小；如果发现过度，可把中间分辨率降为 2×N 或只做一次滤波。
- `ctx.filter` 等 canvas 原生滤镜在小程序环境支持不稳定，所以滤波在 JS 像素层实现（可控、可测、跨端一致）。
- 不做参数化 UI（不加"去噪强度"选项），默认一套参数；后续需要再加。

## 9. 修订记录（2026-08-03，v2）

用户实测：原方案中的 **4×4 块平均**会把细线条（如眼镜框、耳机边缘）稀释丢失。修订如下：

1. 降采样改回**双线性**（先 4N 中值滤波去噪，再双线性缩到 N）——保留物体边界与细线条；
2. 保留 `medianFilter`（4N 分辨率下不会吃粗线条）与 `denoiseGrid`（只修正孤立杂色点）；
3. 移除 `averageBlocks`、`mapRgb`（及其测试），`mapRgbGrid` 恢复为主入口。

## 10. 修订记录（2026-08-03，v3）

用户实测 v2（中值滤波 + 双线性降采样）：画面更不清晰，细线条仍偏糊、杂色依旧。调研并借鉴开源方案后修订（当前实现见 `docs/项目结构与开发说明.md` 第 3 节）：

1. 参考 **perler-beads-ai**（拼豆图纸生成器）：池化不要用 mean（会产生灰色毛边、稀释细线），改为**格子主导色采样**，再做 **BFS 相似色区域合并**去除量化杂色。
2. 参考 **PixelOE**（保细节像素化）：降采样时做**对比度感知**取舍——块内按亮度分暗/亮两簇，少数簇占比 ≥25% 且两簇 RGB 色差 ≥60 时取少数簇中心色（保住眼镜框/耳机线等细线），否则取多数簇中心色（色块纯净）。
3. 移除 v2 的 `medianFilter` 与“双线性降采样到 N”两步；新增纯函数 `dominantBlocks`（主色采样）、`mapRgb`（RGB 数组→色号）、`mergeGrid`（BFS 区域合并）。
4. 当前管线：4N 中间画布 → `dominantBlocks`（对比度感知主色采样）→ `mapRgb`（CIELAB 最近色）→ `mergeGrid`（色距 ≤12 区域合并）→ `denoiseGrid`（孤立点清理）。
5. 与“交给 AI 修改”方案的关系：本版仍走经典图像处理（免费/离线/可测）；AI 卡通化/润色入口保持预留，需要 API Key 时再接入（主页面 `generate` 内已有调用位注释）。
