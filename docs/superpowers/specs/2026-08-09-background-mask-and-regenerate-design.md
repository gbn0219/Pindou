# AI 抠图背景标记 + 无限预览与按需重新生成 技术设计

> 日期：2026-08-09（Asia/Shanghai）
> 状态：方案评审稿（尚未改动任何代码）
> 范围：两项改进 ——
> 1. AI 抠图模式下背景识别的鲁棒性（不再依赖"白色 + 四边连通"）；
> 2. 免费化（无限预览）+ 预览后"带修改要求重新生成"（原图 + 上一版生成图 + 要求一起给 AI）。

## 0. 结论先行

1. **背景识别：采用「标记色背景」方案（推荐）。** 抠图模式下，提示词要求 AI 把背景统一涂成**纯洋红 #FF00FF**、主体禁止出现该颜色；前端按通道规则识别洋红像素即为背景——**不需要四边连通、不依赖轮廓闭合**，从根本上解决"AI 背景非纯白"和"主体边界不闭合"两类问题。仍是一张图、一次调用、不增加成本，整幅 2k 分辨率都用于图纸。
   - 备选「左图右 mask 拼接」：一张图内左半图纸、右半黑白掩码。掩码更显式，但每半只有约 1024×1024，且模型在同一画布内画两幅内容存在错位/不一致风险。建议先实施标记色，实测不听话再启用备选。
2. **免费化 + 重新生成：** 移除 3 次/图配额与解锁门禁（AI 生成后直接进入完整交互）；展示页新增「修改要求」输入，重新生成时把**原图 + 上一版生成图（清洗后压缩版）+ 用户要求 + 基础提示词**一起发给 AI（仍只生成 1 张图、1 次计费）。

## 1. 现状与问题（基于当前代码核对）

### 1.1 背景识别现状：两处都依赖"白色 + 连通"

- **像素级 `cleanImageData`（miniprogram/utils/background.js）**：从四边 flood fill "近白"像素（RGB 均 ≥230）→ 柔化并入（≥215，两轮）→ 清理背景内孤立噪点 → 置纯白。调用点：`utils/ai.js imageToGrid()`，对所有 AI 生成图无条件执行。
- **网格级 `findBackgroundMask`（miniprogram/utils/pattern.js）**：从网格四边 flood fill "白色系色号"（H1/H2/奶油白等，RGB 均 ≥230），返回布尔掩码；用于不显示编号、不计色块数、导出 `noCodeMask`。
- **提示词现状**：抠图模式要求背景严格 #FFFFFF 纯白（`tools/prompt.js` 与 `cloudfunctions/ai-generate-pattern/prompt.js` 为同步副本，两处一致）。

### 1.2 为什么不够鲁棒

- AI 返回的背景经常不是纯白：近白渐变、米白、浅灰、残留辅助线等 → `cleanImageData` 阈值（230/215）覆盖不到的残留；网格级 flood fill 找不到白色系种子。
- 主体边界不闭合：轮廓有缺口时，白色连通域会把主体内部白色（眼白、高光、白色衣物）也吞成背景（像素级"误洗"、网格级"误标"）。
- 根源：现在的"背景 = 白色 + 连通"是**事后猜测**，模型只被口头要求画白底，没有显式可判定的标记。

### 1.3 配额与预览现状

- 服务端：`ai-generate-pattern` 的 `checkQuota`（MAX_ATTEMPTS=3）、`access` 的 `consumeQuota`（3 次上限；local 模式也调用它）。
- 前端：`utils/session.js` MAX_CANDIDATES=3；展示页"再生成"超过 3 次禁用；锁定态不能缩放/看色号/修改/导出；`onUnlock` 走 `createOrder → unlock`（PAY_MODE=mock）。
- 展示页已有"再生成"（`onRegenerate`），但**复用首次参数**（style/cutout/extra），没有要求输入，也不把上一版图片发给 AI；且 AI 原图在 `imageToGrid` 后即被丢弃，未保存。

## 2. 方案一：抠图背景标记（推荐）

### 2.1 标记色选择：纯洋红 #FF00FF

- 识别判据（通道规则，天然抗 JPEG/模型色偏）：`r ≥ 200 && b ≥ 200 && g ≤ 80`（可放宽为 `r-g ≥ 120 && b-g ≥ 120`）。
- **已核对色卡**：MARD 221 色中没有任何颜色满足该判据（最近为 D5 #B34EC6，RGB 距离 ≈123），主体正常颜色不会误判。
- 洋红与肤色（G1 #FFE4D3）、发色、主流衣物色距离远；提示词再禁止主体出现洋红/紫红。

### 2.2 提示词改动（仅抠图模式分支）

在现有「抠图」段之后追加：

- 背景只允许使用标记色：每个背景像素必须严格等于 RGB(255,0,255)（#FF00FF）纯洋红，不允许近白、米白、浅灰、渐变、晕影或杂色；
- 主体及其轮廓禁止出现洋红色（紫红/洋红衣物需改色）；
- 洋红只是背景占位标记，用于程序识别，最终成品背景仍是白色；
- 主体与洋红背景交界干净利落、无混色；主体以外不得出现原背景物体/阴影/渐变（保留现有要求）。

> 非抠图模式保持原「白色背景」要求与现有清洗逻辑，本次不改。

### 2.3 前端管线改动

1. `utils/background.js`：新增洋红标记识别（或给 `cleanImageData` 加模式参数）：
   - 逐像素通道判据 → 洋红掩码（背景候选）；
   - **覆盖率检查**：洋红像素占比 < 1% 视为模型没听话 → 回退到现有近白清洗逻辑（保证不劣于现状）；
   - 洋红掩码置纯白（dominantBlockRgb 自然取到白色桶）；
   - 复用现有"柔化/孤立噪点"逻辑清理洋红背景内的噪声。
2. `utils/ai.js`：
   - `imageToGrid(dataUrl, size, setKey, opts)` 增加 `cutout` 参数；`imageDataToGrid` 增加可选像素级背景掩码；
   - 分块时，某块洋红像素占比 ≥ 50% → 该格直接推 [255,255,255]（映射为 H1）；否则走原 `dominantBlockRgb → mapRgb`；
   - 网格级 `findBackgroundMask` 不改：背景格是 H1，四边 flood fill 自然标记，色号清单/编号/导出照旧。
3. **背景碎块兜底**：标记色模式下，漂浮在背景中的孤立小分量（无论颜色，上限约 2 个格子面积）一律并入背景，避免 AI 在人物周围生成的不属于主体的孤立像素块残留；噪点上限由前端按盘面格子面积估算传入。
4. **关键收益**：不再依赖"背景从四边连通"——即使轮廓不闭合、背景被主体切成孤立块（如叉腰时手臂间的背景洞），只要 AI 按指令涂了洋红，就全部识别为背景。

### 2.4 方案对比

| 维度 | 标记色背景（推荐） | 一张图左右拼接（图纸 \| mask） |
| --- | --- | --- |
| 成本 | 1 张图 1 次调用 | 1 张图 1 次调用 |
| 图纸分辨率 | 整幅约 2048×2048 | 每半约 1024×1024（104 盘每格约 9.8px，仍够主色分块） |
| 掩码确定性 | 依赖模型涂色 + 通道判据 | 显式黑白掩码，最确定 |
| 内容一致性风险 | 无（只有一张图） | 左右两半可能不一致/错位 |
| 实现复杂度 | 低（background.js + ai.js + prompt） | 中（裁剪两半 + 掩码阈值化 + 对齐） |
| 失败回退 | 洋红占比低 → 回退近白清洗 | 难以优雅回退 |

### 2.5 风险与对策

- 模型不涂洋红（仍画白底/米白）：覆盖率回退兜底，效果不劣于现状；
- 模型把洋红画成偏粉/玫红（如映射到 E6 #EB4172）：以边框主色 + 洋红色系判定 + 颜色容差识别实际背景色，仍映射为白色；
- 主体出现少量洋红像素（如紫红衣服）：逐块"占比 ≥50%"判定 + 仅背景格强制白色，少量杂点当作内容映射到色卡（可接受，且提示词已禁止）；
- 模型把洋红理解成"染色"：提示词明确"洋红是背景占位标记，最终成品背景仍是白色"。

## 3. 方案二：免费化 + 带要求重新生成

### 3.1 免费化（移除配额与门禁）

- `cloudfunctions/ai-generate-pattern/index.js`：删除 `checkQuota` 的 3 次限制（保留登录校验）。
- `cloudfunctions/access/index.js`：`consumeQuota` 直接返回 ok；`createOrder/unlock` 前端不再调用（云函数保留作为历史兼容，注明）。
- `miniprogram/page/index/index.js/.wxml`：删除 local 模式下的 `user.consumeQuota` 调用；"按次计费"弹窗文案改为"按次生成"或移除计费字样。
- `miniprogram/page/pattern/index.js/.wxml/.wxss`：移除锁定态——生成后直接完整交互（缩放/色号/图例/修改/导出全部可用）；删除 `onUnlock` 与锁定 UI；"再生成"不再受 3 次限制。
- `miniprogram/utils/session.js`：去掉 `canGenerate` 限流；候选内存保留上限（建议最近 3~5 张，超出替换最旧）或按决策点简化为只保留当前一张。
- `miniprogram/utils/user.js`：按"自己改出来的孤儿清理"原则，删除不再使用的 consumeQuota/checkAccess/createOrder/unlock 前端封装。

### 3.2 重新生成：原图 + 上一版 + 要求

现状缺口：展示页"再生成"复用首次参数、不传上一版图片；aiSession 未保存 AI 原图。

改动：

1. **保存上一版 AI 原图**：`imageToGrid` 完成背景清洗后，把清洗后的 ImageData 重新编码为 ~768px JPEG（复用 `compressToBase64` 思路或 `canvasToTempFilePath` 存临时文件），存入 `aiSession.params.prevImage`（base64 或临时文件路径），grid 照常生成。
   - 为什么存"清洗后"：上一版若带洋红背景标记，直接发给 AI 会把模型带偏；清洗成白底后再发，并在提示词说明"第二张图的白色背景就是成品背景"。
2. **后端请求**：
   - 重新生成：`images = [原图 base64, 上一版 base64, face-ref.jpg]`；首次生成保持 `[原图, face-ref.jpg]`。
   - `buildPrompt` 增加 `regenerate` 分支：说明「第二张图」是上一版生成结果，仅按其构图/风格/配色微调，主体内容仍以第一张原图为准；用户修改要求进入「额外要求」段。
3. **前端展示页 UI**：锁定去除后，"重新生成"卡片常驻，含输入框「修改要求（例如：嘴巴要微笑、人物比例再大一点）」+ 按钮；重新生成时 `extra = (原 extra ? 原 extra + '；' : '') + 新要求`，其余参数（size/set/style/cutout）沿用。
4. **请求体积**：云函数调用有请求体上限；原图与上一版都按现有 768px 压缩策略（约几百 KB 级），face-ref 在服务端本地读文件、不进请求体。

### 3.3 与现有 extraReq 的关系

- 主页已有"额外要求"输入框（`extraReq → extra`，首次生成前可填）；
- 预览页"修改要求"是重新生成专用；
- 两者合并进同一个 `extra` 字段即可，提示词结构不变（都是「额外要求」段），无需新增字段。

## 4. 需要你确认的决策点

1. **背景方案**：标记色（推荐）还是左右拼接 mask？→ 建议先做标记色，开发时各出 2~3 张真实生成图验证。
2. **是否彻底移除锁定/解锁**：既然不收费，建议生成后直接完整交互；若想保留"先看纯色预览、确认后再交互"的 UX，可保留锁定态但移除次数限制——请明确。
3. **候选保留**：重新生成后是否保留历史候选可来回切换？（建议本期只保留最新一张，最简；要"对比上一版"再扩展。）
4. **首次生成确认弹窗**：免费后是否保留"将生成…继续吗"弹窗？（建议保留轻量提示，去掉计费字样。）

### 已确认结论（2026-08-09 用户拍板）

1. 背景方案：**标记色（洋红 #FF00FF）**；
2. 锁定/解锁：**彻底移除**，生成后直接进入完整交互；
3. 候选：**保留历史候选**，展示页提供上一版/下一版切换，用户选最满意的版本（内存保留上限 5 版，超出替换最旧）；
4. 首次生成确认弹窗：**保留**，去掉"计费"字样。
