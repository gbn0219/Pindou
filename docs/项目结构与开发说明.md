# 项目结构与开发说明

> 本文面向后续开发者：先读本文 + `AGENTS.md`，即可了解项目全貌，无需通读所有源码。

## 1. 这是什么

拼豆（拼拼豆）图纸生成微信小程序：导入图片 → 选择生成方式（照片还原 / AI 生成）→ 像素化并映射到 MARD 标准色 → 生成可照着拼的图纸 → 查看/修改/导出。

## 3. 核心数据与算法

- 色卡：`miniprogram/data/colors.json`（221 色主表 + 48/72/144/221 套装成员），由 `scripts/build-colors.js` 从 `docs/拼豆标准色彩RGB与拼豆盘尺寸.md` 生成；运行时加载 `colors.js`（同一份数据）
- **照片还原（方式一，默认）**：选图后先经过裁剪页（可选）→ offscreen canvas 建 4N×4N 中间画布按 contain 绘制（白底、透明按白）→ `averageBlocks`（4×4 块平均 → N×N RGB，仅此一步采样，无平滑/合并/去噪）→ `mapRgb`（CIELAB 最近色，只允许当前套装内色号）→ 色号二维数组。免费离线，支持 52/78/104
- **AI 生成（方式二）**：选图 → 裁剪页（可选）→ 主页选 AI 生成 + 风格（可选「抠出人物背景变白」开关）→ 原图压缩为 ~768px JPEG base64 → 本地代理服务 tools/ai-generate-server.js（读取根目录 .env 的 ARK_API_KEY，默认端口 8787）→ 火山方舟 OpenAI 兼容接口调豆包 Seedream（doubao-seedream-5-0-260128）图像生成模型，多图输入：原图 + 风格提示词 + 一张参考拼图（两张原图转像素图示例，合并为 ref-pack.jpg 随请求发送）+ 一张五官画法示例拼图（5 张拼豆像素画人脸合成，合并为 face-ref.jpg 随请求发送，仅学习五官画法、禁止复制示例角色），size 统一取 2K（约 2048×2048，前端按盘面 floor 分块），watermark 关闭 → 输出像素风格图纸（URL 24h 有效，服务端立即下载转 base64）→ 前端把图片写临时文件、offscreen canvas 读整幅像素 → 背景处理（抠图模式：洋红 #FF00FF 标记色识别，未检测到标记色回退近白清洗）→ `dominantBlockRgb` 主色分块（标记色背景占比 ≥50% 的格强制映射白色）→ CIELAB 最近色映射到当前套装色号 → 色号二维数组。**不输出文字色号，无输出 token 上限问题**。免费，支持 52/78/104，前端有确认弹窗；重新生成时把原图 + 上一版生成图 + 修改要求一起发给 AI
- 风格：内置 5 个示例（卡通、马卡龙、扁平插画、复古像素、水彩），输入框填写自定义风格关键词时以自定义为准
- AI 优化图纸：已移除（不再保留入口与后端）
- 图纸共享：`getApp().globalData.pattern = { grid, size, set, imagePath, mode, style }`（mode: 'photo' | 'ai'），仅内存、不持久化
- 用户中心与门禁：创意生成需登录；免费模式不限制预览/生成次数，生成后直接完整交互并自动入库 `gallery`；云函数 `account` / `access` / `gallery`，集合 `users` / `ai_sessions` / `gallery` / `orders`
- 计数：`utils/pattern.js` 的 `countColors(grid, setCodes)` 按套装顺序统计各色号豆子数量
- 图片加载：`utils/image.js` 在加载前把图片复制到每次唯一的临时路径（时间戳+随机数），绕开 iOS `OffscreenCanvas.createImage` 对同一路径只触发一次 onload 的缓存 bug；带 15s 超时与一次自动重试

## 4. 渲染与画布

- 展示/修改页共用 `utils/pattern.js` 的 `renderGrid`/`drawCell`：每格色块 + 格线留隙 + 居中色号（cellSize=20px、gap=1px）
- 画布放在 `movable-area > movable-view(scale)` 中：页面 JS 先测量展示区，计算"铺满+居中"的初始缩放 `initScale` 与位移 `viewX/viewY`，并把 `canvasPx`（画布总长）同时应用到 movable-view 与 canvas 的样式
- 修改页触摸定位依赖 `scale`：`col = floor(touch.x / scale / (CELL+GAP))`；缩放事件更新 `scale`；轻点判定：位移 ≤16px 且耗时 ≤400ms 才视为点格涂色，拖拽移动不触发涂色
- 修改页画布区是 flex 弹性高度，首次测量可能拿到 0 尺寸：`draw()` 会等尺寸非 0 再绘制（最多重试 8 次）；movable-view 关闭了位置动画（`animation="{{false}}"`）且不使用 `out-of-bounds`，避免初始定位把画布带出视野
- 导出：分辨率切换为 16px/格（避免 104 格时画布超过部分设备 2048px 上限），导出后恢复
- 编号显示：展示/修改页默认铺满视图隐藏编号（纯色图预览清晰）；放大到每格 ≥13.6px（scale ≥0.65）自动显示编号；导出图固定带编号
- 已知待真机确认点：canvas 在 movable-view 缩放下的触摸坐标换算、低端机大画布内存

## 6. AI 生成后端（本地服务 / 云函数）

- 本地模式（开发默认，`config.aiGenerate.backend = 'local'`）：
  - `tools/ai-generate-server.js`：读取项目根目录 `.env` 的 `ARK_API_KEY`，监听 `0.0.0.0:8787`
  - 启动：`node tools/ai-generate-server.js`（开发者工具需勾选"不校验合法域名"）
  - 异步任务：POST /ai-generate 提交后立即返回 taskId（wx.request 单次最长 60s，生成可能超时），客户端每 3s 轮询 GET /ai-generate/status?taskId=xx，最长等待 5 分钟
  - 真机调试：手机与电脑连同一 Wi-Fi，把 `config.aiGenerate.localUrl` 改为电脑局域网 IP（服务启动日志会打印可用 IP，如 `http://10.210.135.185:8787`）；Windows 防火墙需放行 8787；用"真机调试"模式打开；若报 ERR_ADDRESS_UNREACHABLE 表示手机到电脑无路由（不同网络或 AP 隔离），改用手机热点：手机开热点 → 电脑连热点 → 按启动日志的新 IP 更新 localUrl
  - 密钥不打包进小程序；`.env` 已在 .gitignore，另附 `.env.example`
- 云函数模式（`backend = 'cloud'`）：
  - 目录：`cloudfunctions/ai-generate-pattern/`（调度：start/status + 延时触发 worker）与 `cloudfunctions/ai-generate-worker/`（执行：Seedream 生成 + 上传云存储），均 wx-server-sdk、云端安装依赖
  - 部署：微信开发者工具右键该目录 →"上传并部署（云端安装依赖）"
  - 异步任务：客户端 `wx.cloud.callFunction` 单次等待约 15s 即超时（-404012），且云函数单次执行上限固定 60s，故拆成两层：`action:'start'`（写 `ai_tasks` 记录 + 生成参数 JSON 到云存储 → 云调用 `addDelayedFunctionTask` 延时约 7s 触发 `ai-generate-worker` → 立即返回 taskId）→ worker 独立调用（完整 60s 预算）调 Seedream 生成 → 结果上传云存储 `ai-tasks/<openid>/<taskId>.<ext>` → 前端每 3s 轮询 `action:'status'` 拿到 fileID 后 `downloadFile` 下载；任何环节失败（含 worker `status:'error'`、轮询超时）自动重新提交（最多 3 次），失败只提示“生成失败，请稍后重试”，不暴露云函数原始报错
  - 环境变量：`ARK_API_KEY`（必填）、`ARK_MODEL`（可选，默认 doubao-seedream-5-0-260128），配置在 `ai-generate-worker`；`ai-generate-pattern` 无需密钥，仅负责调度；worker 与本地服务同为 Seedream 图像方案（部署目录含 face-ref.jpg 与 prompt.js）；`ai-generate-pattern` 目录的 `config.json` 声明云调用权限 `cloudbase.addDelayedFunctionTask`（重新部署后权限缓存约 10 分钟）；需在控制台创建集合 `ai_tasks`（代码会尝试自动创建）；云函数超时保持默认 60s——生成在 worker 独立调用中执行，无需（也无法）调大
- 调用链路：`page/index/index.js` 的 AI 生成分支 → `utils/ai.js` 的 `compressToBase64` + `callAiGenerate`（按 backend 分发：wx.request 本地服务，或云函数 start/status 异步任务 + 云存储下载）→ 得到 `{ image }`（AI 图纸 data URL）→ `imageToGrid` 主色分块读像素并映射色号 → 二维 grid
- 门禁与配额：免费模式已移除配额；cloud 模式云函数 `ai-generate-pattern` 仅校验登录，local 模式不再调用 `access.consumeQuota`（该云函数直接放行）
- 费用：免费；前端点击时保留确认弹窗（去掉计费字样）

## 7. 常见改动指引

- 改色卡：只改 `docs/拼豆标准色彩RGB与拼豆盘尺寸.md`，再运行 `node scripts/build-colors.js`（会校验 221/48/72/144 与子集关系）
- 改匹配算法：改 `miniprogram/utils/color.js`，同步更新 `tests/color.test.js`
- 改画布外观（格线、字号、色号显示）：改 `miniprogram/utils/pattern.js` 的 `renderGrid`/`drawCell`
- 改页面样式：优先用 `miniprogram/styles/tokens.wxss` 里的令牌，不要散落魔数
- 加新页面：在 `miniprogram/app.json` 的 `pages` 注册，并按 `page/` 下现有页面四件套（js/json/wxml/wxss）组织
