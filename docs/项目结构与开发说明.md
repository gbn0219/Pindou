# 项目结构与开发说明

> 本文面向后续开发者：先读本文 + `AGENTS.md`，即可了解项目全貌，无需通读所有源码。

## 1. 这是什么

拼豆（拼拼豆）图纸生成微信小程序：导入图片 → 像素化并映射到 MARD 标准色 → 生成可照着拼的图纸 → 查看/修改/导出。

## 2. 三个页面与交互

| 页面 | 路径 | 职责 |
| --- | --- | --- |
| 主页面 | `miniprogram/page/index/index` | 选图（wx.chooseMedia）、选色系、选盘大小、生成图纸 |
| 裁剪页 | `miniprogram/page/crop/index` | 任意比例裁剪：拖动框内部移动、拖动四边/四角调整大小；canvas 裁切导出临时图回传主页 |
| 展示页 | `miniprogram/page/pattern/index` | canvas 渲染图纸（每格色号+格线）、色号数量清单、导出 PNG、进入修改 |
| 修改页 | `miniprogram/page/pattern-edit/index` | 底部色板选色 → 点格子涂色；返回展示页自动刷新 |

## 3. 核心数据与算法

- 色卡：`miniprogram/data/colors.json`（221 色主表 + 48/72/144/221 套装成员），由 `scripts/build-colors.js` 从 `docs/拼豆标准色彩RGB与拼豆盘尺寸.md` 生成；运行时加载 `colors.js`（同一份数据）
- 生成（平滑方案 v4，保线保色）：选图后先经过裁剪页（可选）→ offscreen canvas 建 4N×4N 中间画布按 contain 画入（白底、透明按白）→ 格子代表色采样（dominantBlocks：默认 4×4 块平均忠实原图色；亮度对比度 ≥200 且少数簇 ≥40% 时取少数簇多数拼豆色保细线）→ CIELAB 最近色匹配（mapRgb，只允许当前套装内色号）→ 相似色区域合并（mergeGrid：色距 ≤12 的 BFS 区域合并，去量化杂色）→ 孤立点平滑（denoiseGrid）→ 色号二维数组
- AI 卡通化：是另一独立功能（原图卡通化），本期未实现，主页面 generate 内仅留调用位注释
- AI 优化图纸（展示页）：把**原图（裁剪后 imagePath）与当前图纸**一起发送给 AI（基于原图优化，避免不像原图）。后端两种模式：本地代理服务 `tools/ai-optimize-server.js`（读根目录 `.env` 的 `DASHSCOPE_API_KEY`，`config.aiOptimize.backend='local'`）或云函数 `ai-optimize-pattern`（`backend='cloud'`）。提示词：人物/物体及五官特征与原图一致、边界清晰尽量黑色描边、平滑内部颜色、配色与原图一致、不加文字。结果前端重新像素化为新图纸。按次计费，前端有确认弹窗
- 图纸共享：`getApp().globalData.pattern = { grid, size, set, imagePath }`，仅内存、不持久化
- 计数：`utils/pattern.js` 的 `countColors(grid, setCodes)` 按套装顺序统计各色号豆子数量

## 4. 渲染与画布

- 展示/修改页共用 `utils/pattern.js` 的 `renderGrid`/`drawCell`：每格色块 + 格线留缝 + 居中色号（cellSize=20px、gap=1px）
- 画布放在 `movable-area > movable-view(scale)` 中：页面 JS 先测量展示区，计算"铺满+居中"的初始缩放 `initScale` 与位移 `viewX/viewY`，并把 `canvasPx`（画布总长）同时应用到 movable-view 与 canvas 的样式
- 修改页触摸定位依赖 `scale`：`col = floor(touch.x / scale / (CELL+GAP))`；缩放事件更新 `scale`
- 导出：分辨率切换为 16px/格（避免 104 格时画布超过部分设备 2048px 上限），导出后恢复
- 编号显示：展示/修改页默认铺满视图隐藏编号（纯色图预览清晰）；放大到每格 ≥13.6px（scale ≥0.65）自动显示编号；导出图固定带编号
- 已知待真机确认点：canvas 在 movable-view 缩放下的触摸坐标换算、低端机大画布内存

## 6. AI 优化后端（本地服务 / 云函数）

- 本地模式（开发默认，`config.aiOptimize.backend = 'local'`）：
  - `tools/ai-optimize-server.js`：读取项目根目录 `.env` 的 `DASHSCOPE_API_KEY`，监听 `127.0.0.1:8787`
  - 启动：`node tools/ai-optimize-server.js`（开发者工具需勾选"不校验合法域名"）
  - 密钥不打包进小程序；`.env` 已在 .gitignore 中，另附 `.env.example`
- 云函数模式（`backend = 'cloud'`）：
  - 目录：`cloudfunctions/ai-optimize-pattern/`（wx-server-sdk，云端安装依赖）
  - 部署：微信开发者工具右键该目录 → "上传并部署（云端安装依赖）"
  - 环境变量：`DASHSCOPE_API_KEY`（必填）、`DASHSCOPE_MODEL`（可选，默认 qwen-image-2.0-pro）
- 调用链路：`page/pattern/index.js` 的 `aiOptimize` → `renderGridToBase64` + `loadOriginalBase64`（原图）→ `callAiOptimize`（按 backend 分发：wx.request 本地服务 或 wx.cloud.callFunction）→ 得到 `imageBase64`/`fileID` → `saveBase64ToFile`/`downloadFile` → `reprocess`（复用 dominantBlocks/mapRgb/mergeGrid/denoiseGrid）→ 刷新图纸与图例
- 费用：按千问图像编辑模型调用次数计费（每次约 20 秒）；前端点击时弹确认框

## 7. 常见改动指引

- 改色卡：只改 `docs/拼豆标准色彩RGB与拼豆盘尺寸.md`，再运行 `node scripts/build-colors.js`（会校验 221/48/72/144 与子集关系）
- 改匹配算法：改 `miniprogram/utils/color.js`，同步更新 `tests/color.test.js`
- 改画布外观（格线、字号、色号显示）：改 `miniprogram/utils/pattern.js` 的 `renderGrid`/`drawCell`
- 改页面样式：优先用 `miniprogram/styles/tokens.wxss` 里的令牌，不要散落魔法值
- 加新页面：在 `miniprogram/app.json` 的 `pages` 注册，并按 `page/` 下现有页面四件套（js/json/wxml/wxss）组织
