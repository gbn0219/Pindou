# 项目结构与开发说明

> 本文面向后续开发者：先读本文 + `AGENTS.md`，即可了解项目全貌，无需通读所有源码。

## 1. 这是什么

拼豆（拼拼豆）图纸生成微信小程序：导入图片 → 选择生成方式（照片还原 / AI 生成）→ 像素化并映射到 MARD 标准色 → 生成可照着拼的图纸 → 查看/修改/导出。

## 2. 四个页面与交互

| 页面 | 路径 | 职责 |
| --- | --- | --- |
| 主页面 | `miniprogram/page/index/index` | 选图（wx.chooseMedia）、选色系（48/72/144/221）、选盘大小（52/78/104）、选生成方式与风格、生成图纸 |
| 裁剪页 | `miniprogram/page/crop/index` | 任意比例裁剪：拖动框内部移动、拖动四边/四角调整大小；canvas 裁切输出临时图回传主页 |
| 展示页 | `miniprogram/page/pattern/index` | canvas 渲染图纸（每格色号+格线）、色号数量清单、导出 PNG、进入修改 |
| 修改页 | `miniprogram/page/pattern-edit/index` | 底部色板选色 → 点格子涂色；返回展示页自动刷新 |

## 3. 核心数据与算法

- 色卡：`miniprogram/data/colors.json`（221 色主表 + 48/72/144/221 套装成员），由 `scripts/build-colors.js` 从 `docs/拼豆标准色彩RGB与拼豆盘尺寸.md` 生成；运行时加载 `colors.js`（同一份数据）
- **照片还原（方式一，默认）**：选图后先经过裁剪页（可选）→ offscreen canvas 建 4N×4N 中间画布按 contain 绘制（白底、透明按白）→ `averageBlocks`（4×4 块平均 → N×N RGB，仅此一步采样，无平滑/合并/去噪）→ `mapRgb`（CIELAB 最近色，只允许当前套装内色号）→ 色号二维数组。免费离线，支持 52/78/104
- **AI 生成（方式二）**：选图 → 裁剪页（可选）→ 主页选 AI 生成 + 风格 → 原图压缩为 ~768px JPEG base64 → 后端（local/cloud）→ 百炼 OpenAI 兼容接口调 qwen3-vl-plus 多模态模型，system 消息携带完整色表与输出规则，`tools.submit_pixel_pattern` 以 JSON schema 严格约束（style / board_size=52 / color_set / grid 恰好 2704 个色号、行优先），`tool_choice` 强制调用 → 后端校验后返回 JSON grid → 前端再次校验后渲染。按次计费，仅支持 52×52，前端有确认弹窗
- 风格：内置 5 个示例（卡通、马卡龙、扁平插画、复古像素、水彩），输入框填写自定义风格关键词时以自定义为准
- AI 优化图纸：已移除（不再保留入口与后端）
- 图纸共享：`getApp().globalData.pattern = { grid, size, set, imagePath, mode, style }`（mode: 'photo' | 'ai'），仅内存、不持久化
- 计数：`utils/pattern.js` 的 `countColors(grid, setCodes)` 按套装顺序统计各色号豆子数量
- 图片加载：`utils/image.js` 在加载前把图片复制到每次唯一的临时路径（时间戳+随机数），绕开 iOS `OffscreenCanvas.createImage` 对同一路径只触发一次 onload 的缓存 bug；带 15s 超时与一次自动重试

## 4. 渲染与画布

- 展示/修改页共用 `utils/pattern.js` 的 `renderGrid`/`drawCell`：每格色块 + 格线留隙 + 居中色号（cellSize=20px、gap=1px）
- 画布放在 `movable-area > movable-view(scale)` 中：页面 JS 先测量展示区，计算"铺满+居中"的初始缩放 `initScale` 与位移 `viewX/viewY`，并把 `canvasPx`（画布总长）同时应用到 movable-view 与 canvas 的样式
- 修改页触摸定位依赖 `scale`：`col = floor(touch.x / scale / (CELL+GAP))`；缩放事件更新 `scale`
- 修改页画布区是 flex 弹性高度，首次测量可能拿到 0 尺寸：`draw()` 会等尺寸非 0 再绘制（最多重试 8 次）；movable-view 关闭了位置动画（`animation="{{false}}"`）且不使用 `out-of-bounds`，避免初始定位把画布带出视野
- 导出：分辨率切换为 16px/格（避免 104 格时画布超过部分设备 2048px 上限），导出后恢复
- 编号显示：展示/修改页默认铺满视图隐藏编号（纯色图预览清晰）；放大到每格 ≥13.6px（scale ≥0.65）自动显示编号；导出图固定带编号
- 已知待真机确认点：canvas 在 movable-view 缩放下的触摸坐标换算、低端机大画布内存

## 6. AI 生成后端（本地服务 / 云函数）

- 本地模式（开发默认，`config.aiGenerate.backend = 'local'`）：
  - `tools/ai-generate-server.js`：读取项目根目录 `.env` 的 `DASHSCOPE_API_KEY`，监听 `0.0.0.0:8787`
  - 启动：`node tools/ai-generate-server.js`（开发者工具需勾选"不校验合法域名"）
  - 真机调试：手机与电脑连同一 Wi-Fi，把 `config.aiGenerate.localUrl` 改为电脑局域网 IP（服务启动日志会打印可用 IP，如 `http://10.210.135.185:8787`）；Windows 防火墙需放行 8787；用"真机调试"模式打开
  - 密钥不打包进小程序；`.env` 已在 .gitignore，另附 `.env.example`
- 云函数模式（`backend = 'cloud'`）：
  - 目录：`cloudfunctions/ai-generate-pattern/`（wx-server-sdk，云端安装依赖）
  - 部署：微信开发者工具右键该目录 →"上传并部署（云端安装依赖）"
  - 环境变量：`DASHSCOPE_API_KEY`（必填）、`DASHSCOPE_MODEL`（可选，默认 qwen3-vl-plus）
- 调用链路：`page/index/index.js` 的 AI 生成分支 → `utils/ai.js` 的 `compressToBase64` + `callAiGenerate`（按 backend 分发：wx.request 本地服务 或 wx.cloud.callFunction）→ 得到 `{ grid }` → `parseGridResponse` 校验 → 二维 grid
- 费用：按 qwen3-vl-plus 调用 token 计费（图片 + 2704 个色号输出）；前端点击时弹确认框

## 7. 常见改动指引

- 改色卡：只改 `docs/拼豆标准色彩RGB与拼豆盘尺寸.md`，再运行 `node scripts/build-colors.js`（会校验 221/48/72/144 与子集关系）
- 改匹配算法：改 `miniprogram/utils/color.js`，同步更新 `tests/color.test.js`
- 改画布外观（格线、字号、色号显示）：改 `miniprogram/utils/pattern.js` 的 `renderGrid`/`drawCell`
- 改页面样式：优先用 `miniprogram/styles/tokens.wxss` 里的令牌，不要散落魔数
- 加新页面：在 `miniprogram/app.json` 的 `pages` 注册，并按 `page/` 下现有页面四件套（js/json/wxml/wxss）组织
