# 页面重设计方案

> 目标：在不大改业务流程和后端的前提下，统一小程序的信息层级、留白、控件样式和交互反馈。优先用现有 Hum 设计令牌做“视觉整理”，不做投机性抽象。

## 设计原则

1. **先保留，再优化**
   - 不改页面核心信息架构和用户流程。
   - 只调整层级、间距、控件状态、按钮位置和反馈方式。

2. **一套视觉语言**
   - 沿用现有暖纸色、墨色主色、黄色主按钮、红色强调色。
   - 统一卡片圆角、阴影、内边距、分区标题、按钮、分段控件、列表行和底部操作栏。

3. **轻量、稳定、可验证**
   - 优先纯 WXSS / WXML 调整。
   - 少量 JS 只服务于状态展示和交互反馈。
   - 每轮改动都要能通过现有单测、node --check 和微信开发者工具编译。

## 通用组件规则

- 页面背景：继续使用暖纸色。
- 卡片：统一大圆角、轻阴影、适内边距，避免页面看起来被挤成一团。
- 主按钮：黄色主色，固定在页面底部或关键流程终点。
- 次按钮：纸灰色或描边按钮，不与主按钮抢焦点。
- 分段控件：用于互斥选项，当前项高亮。
- 列表行：统一左标题、右箭头或右操作。
- 底部操作栏：关键操作固定底部，注意 safe-area。

## 全屏拼豆界面

- 只保留“智能拼豆”和“一键跟拼”。
- 默认进入智能拼豆。
- “数量 / 颜色”作为排序方式说明的右侧分段控件。
- 当前颜色使用小卡片展示：色块 + 色号 + 数量。
- 一键跟拼时，右侧固定“拼完了”主按钮。
- 底部颜色栏只显示一行，可继续滚动。

## 图纸展示页

- 图纸卡片保留“画纸”观感：圆角外框、细描边、轻阴影。
- 网格区域使用更干净的白色画布和极淡点阵背景。
- 元信息压缩为轻量摘要行。
- 底部“修改 / 导出”保持稳定主次关系。
- 坐标数字加粗、颜色加深，并按设备像素比渲染，避免发虚。

## 图纸修改页

- 工具栏（涂色 / 换色 / 吸色）与调色盘分层。
- 当前选中色状态单独展示。
- 调色盘继续按色系分区。
- 保存操作固定底部。

## 主页面

- 设置项按“图片导入 / 色系 / 生成方式 / 盘面大小 / 附加选项”分组。
- 分组间留白统一。
- “开始生成”固定为页面底部主 CTA。

## 裁剪页

- 画布最大化，控制项收紧到底部。
- 比例选择使用统一分段控件。
- “重置 / 完成”一主一次。

## 图库

- 卡片比例、缩略图、标题、元信息与操作按钮统一。
- 操作按钮只保留“预览 / 编辑”等核心动作。
- 分页控件轻量化。

## 个人中心

- 用户信息卡与菜单列表分成两个清晰模块。
- 菜单行统一为“标题 + 右箭头”。
- 减少重复边框和分组噪声。

## 反馈页

- 表单卡聚焦。
- 说明文字和输入区分层。
- 提交按钮固定底部。

## 实施节奏

1. 基础样式统一
2. 全屏拼豆界面
3. 展示页 / 修改页
4. 主页面 / 裁剪页
5. 图库 / 个人中心 / 反馈

## 验证

- node --check 所有改动 JS。
- 运行现有 node 单测。
- 微信开发者工具编译。
- 手动检查全屏、缩放、排序、智能拼豆、一键跟拼、导出、图库预览、safe-area。
